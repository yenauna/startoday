# startoday
오늘의 별


### 교실 수업도구
교사 화면의 **수업도구** 탭 또는 교실 화면 오른쪽 위 **🧰 수업도구**에서 위젯 보드를 엽니다. 타이머·스톱워치·타이핑 판서·음성 안내·랜덤뽑기·QR 창을 함께 띄우고 제목을 끌거나 오른쪽 아래 모서리로 크기를 조절할 수 있습니다. 첫 도구는 캔버스를 넓게 채워 열리며, ⛶ 버튼은 브라우저 전체화면 대신 캔버스 내부 최대화/복원으로 동작합니다. 보드를 닫거나 다른 앱 탭으로 이동하면 시간 측정과 음성 안내는 멈춥니다.

내 문장과 직접 만든 추첨 목록만 이 브라우저의 `startoday-tools-v1` 키에 저장합니다. 도구는 학급 DB나 Supabase에 쓰지 않습니다. TTS는 브라우저/기기의 한국어 음성 지원이 필요하며, 알림음은 기기 음량·브라우저 오디오 정책을 따릅니다. QR은 URL과 한글을 포함한 UTF-8 텍스트를 외부 서비스 없이 로컬에서 생성합니다.

렌더링 회귀 검증은 Playwright가 준비된 개발 환경에서 `node tests/layout.browser.mjs`로 실행할 수 있습니다. 별도 설치 경로는 `PLAYWRIGHT_MODULE`, Chromium 실행 파일은 `CHROMIUM_EXECUTABLE_PATH` 환경 변수로 지정합니다. 390px/데스크톱의 기록 기준선, 과목 버튼 크기·글씨, 캔버스 내부 최대화와 복원을 실제 브라우저에서 검사합니다.

### 독립 앱과 도구 배치
HTTPS 사이트의 **앱 설치** 또는 브라우저의 설치 메뉴로 주소창 없는 독립 앱을 실행할 수 있습니다. 보드 상단 **전체화면**은 보드 전체를 모니터에 맞추고, 각 창의 **⛶**는 캔버스 내부 최대화/복원으로 동작합니다. **도구 메뉴 접기**는 플로팅 버튼만 남깁니다. 도구별 창 위치·크기는 이 브라우저의 `startoday-tool-layouts-v1`에 저장하며, 다음에 열 때 화면 범위에 맞춰 복원합니다. 서비스워커는 학급 데이터나 인증 응답을 캐시하지 않고 기존 네트워크 연결을 그대로 사용합니다.

판서는 칠판에서 직접 타이핑하고 선택한 글자에 서식을 적용합니다. 음성 안내는 기기에 설치된 한국어 목소리와 속도·음조를 선택할 수 있습니다. 과목 편집창의 추천 배경과 포인트색은 교사가 선택해 저장할 때만 적용합니다.

일정 시간대는 새로 저장할 때 `timeOfDay`에 의미를 기록하고 `0=아침`, `7=점심`, `8=방과후`를 사용합니다. 이 필드가 없는 이전 데이터의 `7=방과후`, `8=점심`은 그대로 해석하므로 기존 일정을 일괄 변경하지 않습니다.

### 과제 진행도와 하루 시간표 (2단계 11차)
과제 달력 날짜의 **+**에서 바로 등록하고, 과제를 누르면 학생 카드로 상태를 체크합니다. 카드 클릭은 진행중 → 완료 → 안함, 길게 누르기/우클릭은 상세 상태·메모 편집입니다. **남은 진행중 전체 안함**는 대상 학생 중 출결 제외가 아닌 진행중 상태만 변경합니다. 완료는 +1 칭찬, 안함은 -1 조언, 늦게완료·면제는 0점 기록이며 단순 체크리스트는 자동 기록을 만들지 않습니다. 기존 과제 자동 기록은 교사 자료를 열 때 이 기준으로 갱신하고 ID·생성 시각·직접 작성 기록은 보존합니다.

**설정 → 학사일정 → 점심시간 위치**에서 3/4/5교시 후를 고르면 교사·교실·학생·일정 화면에 함께 반영됩니다. 학생 화면에는 지난 날짜의 진행중 과제도 표시됩니다. 공지와 판서는 숫자 pt 및 4×5 색상 카드로 선택한 글자의 서식을 바꾸며, 과목 추천 카드는 배경·포인트색을 함께 적용합니다. 창체 계열의 새 기본값은 라벤더이며 직접 지정한 색과 출처가 불명확한 저장 색은 유지합니다.

**클라우드 적용:** Supabase SQL Editor에서 최신 `schema.sql`을 다시 실행해야 학생 화면의 밀린 과제, 점심 위치·시간대, 새 과제 점수 기준이 안전한 읽기 응답에도 반영됩니다. 기존 테이블과 인증/RLS 정책을 보존하는 함수 갱신입니다. 저장소 반영만으로 운영 DB에 SQL이 실행되지는 않습니다.

검증: `node --test --test-isolation=none tests/*.test.js`, `npm run check`, `node tests/sql.integration.mjs`, `python build-demo.py`. Playwright 환경에서는 `node tests/practice11.browser.mjs`로 모바일 카드·일괄 체크·확인자·날짜 등록·서식 카드·학생 공개 정보/시간표를 추가 검증합니다.

### 기록·과제 진입과 학생 서식 (2단계 12차)
빠른 기록에서 교시를 입력하거나 직접 선택하면 **기록 날짜**의 시간표를 찾아 `subjectCode`와 `[과목명]` 본문 접두어를 함께 저장합니다. 시간표가 없으면 과목을 임의로 넣지 않습니다. 과제 표의 제목과 달력 과제는 같은 학생 카드 모달로 연결되며, 표·모달에서 동일한 **남은 진행중 전체 안함** 작업을 실행합니다. 확인자는 숨김 토글 대신 항상 펼쳐진 학생/선생님 라디오 카드로 선택합니다.

학생 칭찬 편지는 날짜/교시 다음 줄에 영역 배지와 본문을 나란히 표시합니다. 학생의 아침·점심·방과후 슬롯도 교사와 공통 스타일을 사용합니다. 미래 디데이는 상단 카운트다운으로만 표시하고 대시보드 주간 티커에서는 제외합니다. 이번 변경은 추가 SQL 적용 없이 기존 JSON 저장 구조를 사용하며, 11차 클라우드 함수 적용 안내는 그대로 유효합니다.

### 경험치 칭호
키워드 감지 방식은 15차에서 폐기했습니다. 현재는 교사가 부여한 6대 경험치 영역의 칭찬 횟수로 18개 칭호를 해금합니다. 아래 15차 안내를 참고하세요.

### 학습 명칭·시간 카드·일괄 안함 검증 (2단계 14차)
기본 경험치의 **학습태도**를 **학습**으로 바꿉니다. 기존 영역 행·기록의 `areas`/`area`·과제의 `statArea`는 로컬 복원/클라우드 로드/백업 복원에서 정규화합니다. 두 이름이 한 기록에 있어도 한 번만 집계하며, 중복 영역 행은 활성 행과 기존 순서를 우선해 하나로 합칩니다. 사용자 지정 이름과 기록 ID·원문·생성 시각은 보존합니다. 첫 영역을 별도로 개명했는데 옛 학습 참조가 남았다면 그 이름을 덮어쓰지 않고 학습 영역을 별도로 복구합니다. 별 왕국 칭호는 기존과 같이 칭찬 행동으로 집계하며 영역 개명으로 횟수가 바뀌지 않습니다.

빠른 기록의 **⏰ 시간자동/선택 교시** 버튼은 카드 모달을 엽니다. 자동·미지정·아침·1~6교시·점심·방과후를 선택하면 즉시 반영되고 닫힙니다. 기존 쉬는시간도 유지하며, 점심 카드는 학사일정의 3/4/5교시 후 설정을 따릅니다. 선택 중 작성 내용과 대상 학생은 유지합니다.

`taskStateOps`와 `markRemainingUndoneOps`는 유효한 `YYYY-MM-DD` 날짜만 받습니다. 서버 상태 검증도 `^[0-9]{4}-[0-9]{2}-[0-9]{2}$`와 실제 달력 날짜 검사를 사용하며, 잘못된 상태가 들어간 배치는 앞선 작업까지 원자적으로 롤백합니다.

**Supabase에서 최신 `schema.sql`을 다시 실행하세요.** 영역 이름·참조 마이그레이션과 구 클라이언트 저장값 정규화, 날짜 검증 함수가 포함됩니다. 운영 DB에는 자동 실행하지 않았습니다. 추가 브라우저 검증은 `node tests/practice14.browser.mjs`로 명칭 호환·모바일 시간 카드·점심 순서·일괄 안함을 확인합니다.

### 별명·경험치 칭호·장기 퀘스트 (2단계 15차)
학생 성장 카드의 **별명 설정**에서 완성된 한글 1~8자를 저장하거나 지울 수 있습니다. 공백·숫자·영문·특수문자는 허용하지 않습니다. 학생 화면은 `이름 "별명"`, 교사 카드·명단은 `이름(별명)`으로 표시합니다. 교사가 정한 교실 화면용 별명(`alias`)은 따로 유지합니다.

칭호는 **학습·과제·관계·도전·생활·알바** 경험치의 칭찬 횟수에만 연동합니다. 한 기록의 같은 영역은 한 번만 세며, 제목·내용의 단어는 집계에 사용하지 않습니다. 기존 7대 키워드 감지·추천 코드는 제거했고 기존 키워드 칭호는 더 이상 표시·장착하지 않습니다. 경험치 이름을 바꿔도 기본 영역 ID와 현재 이름으로 연결합니다. **설정 → 경험치 종류 → 칭호 단계별 기준 횟수**의 기본값 15회는 15/30/45회이며, 30회로 바꾸면 30/60/90회가 됩니다.

과제에서 **장기 퀘스트**, 목표 횟수(기본 10), 완료 보상 칭호를 설정합니다. 학생별 `+ 도장`/`−`로 누적하고 날짜가 바뀌어도 시작일 기준 상태 하나에 이어집니다. 목표 달성 시 기본 과제 정책에 따라 완료 칭찬 +1회를 실제 완료일에 기록하며, 별점 미부여 옵션에서는 자동 기록을 만들지 않습니다. 보상 칭호는 학생 `rewardTitles`에 한 번만 영구 추가되어 감소·중단·삭제 후에도 도감에서 장착할 수 있습니다. 도장 수가 줄면 일반 완료 별점은 되돌아가지만 보상 칭호는 남습니다. 퀘스트는 일반 전원 완료/일괄 안함과 또래 검사 대상에서 제외하여 도장 우회를 방지합니다. 기록된 일반 과제를 퀘스트로 바꾸려면 복사해 새로 등록하며, 진행 중인 퀘스트의 시작일은 고정합니다.

음성 안내는 한국어 Natural/신경망 음성, Online/고품질 음성 순으로 기본 선택하며 늦게 로드된 음성 목록에도 반영합니다. 직접 선택한 목소리는 유지합니다. 기본 속도는 0.95x, 음조는 1.0이며 실제 제공 음성과 소리는 브라우저·운영체제에 따릅니다.

**Supabase에서 최신 `schema.sql`을 실행해야 합니다.** `startoday_student_nickname_set`은 학생 본인 인증과 입력 검증 후 별명만 바꿉니다. 6대 칭호 집계·목표 설정·퀘스트 보상 장착과 원자적 도장 검증/영구 보상 보존도 포함합니다. 기존 OAuth·교사 저장·RLS·보고서와 일반 과제 정책을 유지합니다. 운영 DB에 SQL을 자동 실행하지 않았습니다.

검증: 일반 단위 테스트/SQL 통합 테스트 및 `node tests/practice15.browser.mjs`. 차기 학급화폐 상점의 **신비한 별 상자** 설계는 [로드맵](docs/roadmap.md)에 기록했습니다.

### 칭호 기준 횟수 배수 (2단계 16차)
`titleGoal`은 최종 목표가 아닌 **단계별 기준 횟수**입니다. 1·2·3단계는 각각 `[goal, goal × 2, goal × 3]`으로 해금합니다. 기본 15는 15/30/45회, 기준 30은 30/60/90회입니다. 기존 칭찬 기록과 저장된 기준값은 그대로 사용하며, 장기 퀘스트 목표 횟수와 영구 보상 칭호에는 영향을 주지 않습니다.

클라우드 장착 검증을 맞추려면 Supabase에서 최신 `schema.sql`을 다시 실행하세요. 서버의 `startoday_student_title_set`도 같은 배수식을 사용합니다. 운영 DB에는 자동 실행하지 않았습니다.

### 학급화폐·상점 및 체험 자료 (2단계 17차)
교사의 **경제 → 자산 관리**에서 학생별 잔액·보유 수량을 보고 선물하거나 별코인을 지급/차감합니다. **상점 관리**에서는 물품을 등록·수정·삭제하고 환불 허용을 설정합니다. 수량을 비워 두면 무한대이며, 선물도 유한 재고를 차감합니다. 삭제는 판매 중단으로 처리하여 기존 보유 물품과 거래 이력을 보존합니다.

학생은 **내 교실(홈) / 경제 → 내 자산 / 상점**에서 구매·사용·환불합니다. 별코인은 `날짜까지의 (칭찬−지도) 점수 × 10 + 경제 거래 금액 합계`로 계산하며 기존 별 점수·칭호 집계를 바꾸지 않습니다. 미사용 구매만 환불할 수 있고 선물은 환불할 수 없습니다. 환불은 현재 판매가가 아닌 원 구매가로 복구하며 원 구매 차감 내역과 환불 내역을 모두 보존합니다. 교사가 상점 물품을 물리적으로 삭제한 경우에도 구매가는 환급되지만 복원할 재고 행은 없습니다. 앱의 삭제 버튼은 물리적으로 지우지 않습니다.

### 학생 화면·상점·일정 중요도 정리 (2단계 18차)
학생 성장 카드는 별 개수를 한 번만 표시하고 캐릭터 공간을 확보합니다. 대표 칭호는 헤더에 유지하며 본문은 작은 **칭호도감** 버튼 하나로 정리했습니다. 별명은 이름 옆 연필 버튼에서 변경합니다. 학생 화면 렌더링 시 최상단으로 이동하며 교사의 학생 상세 모달 칭호 목록은 기본 접힘입니다.

### 학생 편지함 기간·실제 상품 카테고리·기본 캐릭터
**설정 → 기본 정보 → 학생 화면 → 칭찬 편지함 노출 기간**에서 전체(기본), 최근 30일, 최근 7일, 이번 달을 선택합니다. 최근 기간은 당일을 포함하며 미래 날짜의 칭찬은 해당 날짜부터 표시합니다. 전체 모드의 기존 50건 제한을 제거했습니다. 기간 설정은 편지함에만 적용하며 누적 별 점수·영역 점수·칭호에는 영향을 주지 않습니다. 모든 모드에서 본인의 칭찬만 제공하고 조언·사건·비공개 메모는 포함하지 않습니다.

일반 안내는 교사 대시보드·교실 화면·학생 오늘 일정에 유지합니다. 학생 달력 날짜 칸의 알약에서만 숨기며, 날짜를 선택하면 상세에서 확인할 수 있습니다. 특정 교시의 안내는 해당 교시 수업이 아직 없어도 학생 오늘 일정에 표시합니다.

학생 상점은 현재 상품에 실제 존재하는 카테고리만 생성합니다. 상품이 있는 품절 카테고리는 유지하고 상품이 없어진 카테고리는 제거합니다. 보관함 명패에는 구매/선물 구분 대신 상품 카테고리를 표시합니다. 새 거래에는 `itemCategory`를 보존하여 상품 변경·삭제 뒤에도 원래 분류를 유지합니다. 과거 거래는 삭제 보관된 상품을 포함한 원상품에서 복원하며 원상품과 분류 정보가 모두 없으면 `기타`로 표시합니다. 구매·가격·재고·환불 계산은 그대로입니다.

### 24차: 상점 공동구매 (학급 펀딩)
교사 **경제 → 상점 관리 → 새 물품/쿠폰 등록/수정**에서 **공동구매 물품**을 선택합니다. 금액은 목표 모금액으로 바뀌고 수량은 무제한으로 고정됩니다. 설명을 등록할 수 있으며, 일반 상품과 동일한 카테고리에 진행률 카드가 표시됩니다. 학생은 카드 또는 **함께 모으기(기부)**에서 상세 현황·남은 금액·기여도 순위를 확인하고 금액 입력 및 **+1 / +5 / +10별 / 전액**으로 기여합니다. 전액은 보유 잔액과 남은 목표 중 작은 금액입니다.

기여는 별 점수와 분리된 거래 원장에 차감으로 기록하며, 개인 보관함에는 들어가지 않습니다. 목표를 넘는 요청은 남은 금액으로 보정합니다. 모금 완료 시 추가 기여를 차단하고, 교사가 **보상 사용 완료**를 한 번만 처리할 수 있습니다. 기여가 발생한 보상의 유형 전환·모금액 미만 목표 축소와 달성 후 목표 변경을 막습니다. 기여액은 동일 학생별로 누적되며, 동점은 학생 ID 순으로 표시합니다. 본인 기여는 강조하고 전출 학생은 이름 대신 ‘전출 학생’으로 표시합니다. 공동구매 기여는 개인 구매 환불 대상이 아닙니다.

상세 모달은 본인 기여 후 즉시 갱신됩니다. 로컬의 다른 창 변경도 반영하며 클라우드 상세는 열려 있는 동안 4초 간격으로 인증된 최신 정보를 조회합니다. 학생에게는 참여자의 이름·기여액만 추가로 제공하고 비밀번호·개인 기록·다른 학생의 잔액/거래는 공개하지 않습니다. 학생 기여 RPC는 기존 학교·학년·반·번호·비밀번호 인증과 `p_student_id` 일치를 모두 검사합니다. 교사 사용 RPC는 로그인한 소유자만 호출할 수 있습니다.

**클라우드 적용:** Supabase SQL Editor에서 최신 `schema.sql` 전체를 실행해야 합니다. 기존 자료를 보존하면서 `startoday_shop_items`에 `is_group_buy`, `group_goal`, `group_collected`, `is_funded`, `is_used`를 추가하고 `startoday_group_buy_contribs`와 기여/보상 사용 RPC를 생성합니다. JSONB 백업 형식과 실제 컬럼은 트리거로 동기화하고, 학급 행 잠금으로 잔액 검증·누적 기여·모금 달성·거래 기록을 원자적으로 처리합니다. 최종 트랜잭션에서 기여 합계와 모금액 일치도 검증합니다. 운영 DB에는 이 패치에서 직접 접속하지 않았습니다.

새 체험 데이터에는 **[특별혜택] 금요일 보드게임 파티**(목표 100별, 현재 65별, 가온 30·나래 25·다온 10별)를 포함합니다. 기존 체험 자료는 보존하므로 새 시드는 **체험 자료 초기화** 후 확인합니다. 새 공동구매는 기존 체험 자료에도 직접 등록할 수 있습니다.

SQL 테스트는 개발 의존성 PGlite의 실제 PostgreSQL 엔진에서 재실행 마이그레이션·인증/RLS·실패 롤백·잔액·목표 보정·연속 기여·교사 사용 제한을 검증합니다. 브라우저 테스트는 등록/수정·빠른 금액·기여/달성·잔액·두 창의 순위 갱신·보상 사용·재접속과 360/390/768/1280px 배치를 확인합니다. 기존 경제·상점·프로필·일정/스크롤 및 SQL 회귀 테스트도 유지합니다.

- 학생 프로필의 칭호 배지만 눌러 **칭호도감**을 엽니다. 중복 도감 버튼을 제거했습니다. 칭찬 편지함에 **최근 3개만**(`recent3`)을 추가하며 활동 날짜·최초 작성 시각·ID 내림차순으로 본인의 공개 칭찬 3건만 반환합니다. 별 점수·칭호 계산은 그대로입니다. 일반 상점 카드에서도 설명·가격·본인 잔액·재고를 보는 상세 모달을 열 수 있습니다.
- 학생 명단의 **별명**은 학생이 설정한 `nickname`을 우선 표시하고 기존 `alias`를 대체 표시로 보존합니다. 로컬 창 간 저장 알림은 즉시 반영하며, 클라우드 교사 명단이 열려 있으면 3초 간격으로 최신 자료를 확인합니다. 편집 모달이 열려 있으면 기존처럼 동기화를 보류합니다. 명단 셀만 갱신하여 다른 설정 입력을 초기화하지 않습니다.
- 랜덤뽑기에 **카드 드로우 (한 명씩)**를 추가했습니다. 뽑기마다 한 명이 등장하며 비복원/중복 허용·목록 리셋·개인정보 모드를 기존 후보 로직과 공유합니다. 상자와 카드는 긴 이름을 축소하고 넘침을 잘라 표시하며 전체 이름은 툴팁과 결과에서 확인할 수 있습니다.
- 기록 생성·편집 및 로컬/클라우드 저장에서 비어 있는 `createdAt`을 보정하고 기존 최초 시각은 유지합니다. 기록 카드에는 활동 날짜와 **작성 HH:mm**(한국 시각)을 표시합니다. 작성 시각이 없는 과거 기록은 임의의 시각을 표시하지 않습니다.

**SQL 변경 있음:** 클라우드의 `recent3` 설정 허용·학생 편지함 3건 제한·장기과제 달력 제외·기록 최초 작성 시각 보정을 위해 Supabase에서 최신 `schema.sql` 전체를 실행해야 합니다. 테이블 구조 변경은 없으며 운영 DB에 직접 적용하지 않았습니다.

검증: 기존 184개를 포함한 단위 테스트, `npm run check`, `npm run build`, `tests/patch25.browser.mjs` 및 경제/공동구매/프로필/학생 화면/장기과제/일정 회귀 브라우저, PostgreSQL(PGlite) SQL 회귀 테스트. GitHub Pages는 기존 main 브랜치 루트 배포 설정을 사용합니다.

### 26차: 누적 장기과제·직접 터치 뽑기·선물/회수 서랍
장기과제는 시작일 이전·마감일 이후·출결 제외일에도 교사가 누적 진행도를 수정할 수 있습니다. 날짜는 프로젝트 안내용으로 표시하고 상태의 저장 키는 기존 시작일을 유지합니다. 이미 도장이 있는 프로젝트의 시작일은 저장 키 보존을 위해 고정되며 마감일은 선택 사항입니다. 대상 학생·삭제 여부와 올바른 날짜 형식 검사는 유지합니다.

등록/수정의 **세부 항목 목록**에 줄바꿈으로 항목을 입력하면 `questSubtasks`에 저장하고 항목 수로 목표를 맞춥니다. 중복 없는 항목명(각 200자 이내, 최대 999개)을 사용하며 `completedSubtasks`에는 완료 항목명을 저장하여 순서 변경에도 진행을 보존합니다. 항목 도장판에서 원하는 항목을 자유롭게 체크/해제하며, 기존 숫자 도장을 체크리스트로 바꾸면 앞쪽 항목에 기존 횟수를 대응합니다. 항목 삭제는 해당 진행도를 제거하지만 이미 획득한 칭호는 영구 보존됩니다. 숫자 도장만 있는 기존 장기과제도 그대로 관리할 수 있습니다.

교사 장기과제 카드는 제목·기간·목표·보상·완료/진행 인원만 요약하고 **진행도/도장판 열기**로 상세 관리합니다. 학생 장기과제 영역은 PC에서 전체 열 너비를 사용하며, 시작/마감 시점과 관계없이 삭제되지 않은 본인 프로젝트·완료 항목·남은 항목·도장판을 표시합니다.

랜덤뽑기는 4글자 이름을 번호와 함께 읽을 수 있도록 상자 최소 폭을 150px로 넓혔습니다. 카드 드로우는 중앙 카드 덱을, 룰렛은 원판을 직접 터치/클릭/키보드로 실행합니다. 두 모드의 상단 실행 버튼은 숨기고 카드 터치 영역은 320px 고정 폭(작은 화면은 가용 폭)으로 유지합니다. 뒤집기 애니메이션은 내부 면에만 적용하여 터치 영역의 위치와 크기가 바뀌지 않습니다.

교실 이름 표시 옵션은 **번호와 이름 / 번호만 / 이름 가림 / 별명**입니다. 별명 모드는 학생 `nickname`을 표시하고 없으면 `별{번호}`를 표시합니다.

경제 자산관리의 학생 카드/행을 누르면 바로 아래 **학생 보유함 / 상점 물품 목록** 서랍이 열립니다. 서랍의 선물은 즉시 지급하고, 회수는 확인 후 유한 재고 복구 여부를 선택합니다. 회수는 별코인 잔액을 바꾸지 않고 보유 상태를 `회수됨`으로 기록하며, 별도의 0별코인 `회수` 거래를 남깁니다. 사용·환불·회수한 물품은 다시 회수하지 못합니다. 상점 관리의 개인 물품 카드 **🎁 선물하기**에서는 실제 학생 명단의 번호판으로 지급합니다. 공동구매는 개인 소장이 아니므로 선물/회수 대상에서 제외합니다. 기존 일반 선물 모달도 유지합니다.

**SQL 변경 있음:** 최신 `schema.sql` 전체 실행이 필요합니다. JSONB 체크리스트·완료 항목/횟수 일치 검증, 누적 프로젝트 학생 응답, 교사 전용 회수 및 경제 거래 종류 제약을 추가했습니다. 기존 데이터와 시작일 기반 키를 유지하며 재실행 가능하도록 작성했습니다. 운영 DB에는 직접 적용하지 않았습니다.

검증: `npm test`, `npm run check`, `npm run build`, `node tests/patch26.sql.mjs`, `node tests/patch26.browser.mjs`와 기존 SQL/브라우저 회귀 테스트. 새 검증은 자유 순서 체크·해제, 시작 전/종료 후/제외일 누적, 칭호 영구 보존, 학생 프로젝트 노출·PC 전체 너비, 직접 터치·고정 카드 크기, 서랍/번호판 선물과 재고 선택 회수, 반복 회수·재고 초과 차단을 포함합니다.

### 27차: 장기과제 삭제·교시 일정 편집·당일 메모·안전 선물
장기과제 카드·진행도 모달·수정 모달에 **삭제**를 제공합니다. 확인 후 장기과제를 숨기고 연결된 스탬프 상태와 자동 기록을 함께 정리합니다. 이미 획득한 보상 칭호와 수동 기록은 보존됩니다. 교사 대시보드의 미완료 목록/강조에서는 장기과제를 제외하고 일반 과제와 루틴을 점검합니다.

시간표 슬롯의 일정 텍스트는 시간표 편집과 분리된 일정 편집 버튼입니다. 교시 편집 모달 안에서도 연결 일정의 수정/삭제를 지원합니다. **메모 저장**은 과목을 다시 누르지 않고 저장하며, **메모 지우기**는 공개/당일 메모를 비운 상태로 바로 저장합니다. 기존 메모 지우기 실행취소와 과목 즉시 저장은 유지합니다.

기존 `privateMemo` 필드의 UI 명칭/의미를 **당일 공개 메모 (수업 당일에만 학생 공개)**로 변경했습니다. 기존 필드를 유지하면서 로컬/클라우드 모두 실제 한국 날짜의 오늘 시간표에만 제공합니다. 미래/과거 수업과 학생 달력 데이터에는 포함하지 않고, 오래된 학생 스냅샷도 화면 날짜가 오늘이 아니면 표시하지 않습니다. 일반 수업 메모는 기존 공개 범위를 유지합니다.

학생 장기과제는 제목·스탬프 수를 한 줄로 표시하고, 마감일이 있을 때만 한국어 날짜를, 학생 확인자가 있을 때만 확인자를 추가합니다. 카드를 펼치면 세부 항목과 도장판이 보이며 기본은 접힘입니다. 학생이 도장 상태를 임의 수정할 수 있는 기능은 추가하지 않습니다.

교사 물품 카드는 기본 최대 약 220px로 줄이고, 서랍 상점 목록도 작은 카드로 정돈했습니다. 상점의 선물 번호판은 **번호. 이름**과 선택 상태를 표시합니다. 학생 버튼은 선택만 하고 **선택한 학생(...)에게 선물하기**에서 최종 지급합니다. 펼친 번호판은 가용 폭에서 72px 이상 버튼을 4~6열로 사용하며 작은 화면에서는 줄어듭니다.

선물 직후 **↩ 선물 취소 (5초)**를 제공합니다. 신규 선물 거래의 정확한 ID로만 취소하고, 미사용 선물을 `취소됨`으로 처리하여 유한 재고를 한 개 복구하며 0별코인 `선물취소` 기록을 남깁니다. 이미 사용/회수/취소한 물품이나 5초가 지난 선물은 취소할 수 없습니다. 클라우드는 교사 소유권·학급 잠금과 서버의 거래 생성 시각으로 제한하며 로컬 모드도 같은 검증을 적용합니다. 기존 일반 선물과 서랍 선물에도 실행취소를 제공합니다. 공동구매의 개인 선물 제외 규칙은 유지합니다.

랜덤뽑기는 별빛 펄/골드 상자와 터치 바운스, 별자리 카드 뒷면/반짝임, 파스텔 룰렛·정밀 포인터로 정돈했습니다. 카드의 고정 터치 영역과 키보드 조작, 동작 줄이기 설정을 유지합니다.

**SQL 변경 있음:** Supabase에서 최신 `schema.sql` 전체 실행이 필요합니다. 당일 메모의 학생 응답 범위와 `선물취소` 거래 종류·5초 취소 검증·정확한 선물 ID 반환을 추가했습니다. 기존 JSONB 필드를 유지하며 스크립트 재실행을 검증했습니다. 운영 DB에는 직접 적용하지 않았습니다.

검증: 기존 단위 테스트와 `tests/patch27.test.js`, `tests/patch27.sql.mjs`, `tests/patch27.browser.mjs`, 기존 SQL/브라우저 회귀 및 빌드. 신규 검증은 삭제 경로 3곳, 연결 일정 편집/삭제, 메모 단독 저장/지우기, 당일 공개 경계, 아코디언, 대시보드 필터, 선택/확인 선물, 5초 만료·반복 취소·사용 후 취소·권한 차단을 포함합니다.

### 28차: 학생 캐릭터 숨쉬기·점프
학생 별빛 교실의 캐릭터에 3.2초 호흡과 발밑 그림자 애니메이션을 적용했습니다. 캐릭터를 터치/클릭하거나 키보드 Enter/Space로 누르면 650ms 동안 웅크림·도약·착지·반동과 작은 별가루가 표시된 후 호흡으로 복귀합니다. 진행 중인 점프의 연속 입력은 중복 실행하지 않습니다.

캐릭터 영역을 이름이 있는 실제 버튼으로 바꾸고 숨김 접근성 속성을 제거했으며 포커스 표시를 제공합니다. 점프 중 머리/별가루가 잘리지 않도록 여유 공간을 확보했습니다. `prefers-reduced-motion: reduce`에서는 호흡·그림자·점프·별가루 모션을 끕니다. 캐릭터 이미지·장착 슬롯·별명/칭호와 학생 데이터 저장 동작은 유지합니다.

**DB 및 `schema.sql` 변경 없음.** 검증: 기존 전체 단위 테스트, 프로필·학생 홈·스크롤/반응형 브라우저 회귀, `tests/patch28.browser.mjs`, 구문 검사와 체험 HTML 빌드. 새 브라우저 검증은 실제 터치와 Enter/Space, 정확한 변형 수치, 650ms 뒤 정리/호흡 복귀, 점프 여유 공간, 360/390/768/1280px, 동작 줄이기, 화면 이동 중 타이머 및 학생 데이터 무변경을 확인합니다.

### 29차: 캐릭터 선택 하이라이트 방지
아바타 스테이지·캐릭터 버튼·이미지·별가루에 선택 방지와 WebKit 터치 콜아웃/탭 하이라이트 차단을 적용합니다. 캐릭터 이미지는 `draggable="false"`와 이미지 드래그 차단 CSS를 함께 사용합니다. 마우스/터치의 `:focus` 외곽선은 없애고 키보드 `:focus-visible`의 보라색 3px 포커스 표시는 유지합니다. 키보드 포커스가 남은 버튼을 포인터로 누르는 경우도 입력 방식 표시로 구분하고, 키보드 입력 시 포커스 표시를 복구합니다. 28차의 호흡·점프·동작 줄이기와 데이터 저장 동작은 그대로입니다.

**DB 및 `schema.sql` 변경 없음.** 기존 아바타 브라우저 검증에 연속 마우스 클릭·이미지 드래그·선택 영역 비생성·투명 탭 하이라이트·키보드 Tab 포커스 유지를 추가했습니다.

### 30차: 대각선 별가루·작성 일시 구분
캐릭터 별가루는 정수리 중앙 대신 오른쪽 상단(`top:14%; right:18%`)에서 나타나며, 오른쪽 12px·위쪽 24px로 이동하면서 −10°→15° 회전하여 사라집니다. 기존 점프·접근성·선택 방지·동작 줄이기 동작을 유지합니다.

관찰기록의 작성 일시는 한국 시간(`Asia/Seoul`)의 작성 날짜와 기록 대상 날짜를 비교합니다. 같으면 **작성 HH:mm**, 다르면 **작성 M.D. HH:mm**을 표시합니다. UTC 날짜 문자열을 단순히 잘라 비교하지 않으므로 한국 자정과 연도 경계도 올바르게 처리합니다. 전체 작성 시각 툴팁과 원래 `createdAt` 값은 보존합니다.

**DB 및 `schema.sql` 변경 없음.** 단위 테스트는 당일/소급/다른 연도·한국 자정·잘못된 시각을 확인하고, 실제 기록 카드 및 아바타 브라우저 검증에서 날짜 표시·툴팁·모바일 폭·별가루 위치/회전/이동을 확인합니다.


### 31차: 기록 일시·완료일·장기과제 및 대시보드 정돈
기록 작성 시각은 날짜에 관계없이 한국 시간의 `작성 M.D.(요일) HH:mm`으로 표시하며, 작성 후 1분 이상 지난 수정 시각만 `/ 수정 M.D.(요일) HH:mm`으로 함께 표시합니다. 전체 시각 툴팁과 최초 작성 원본은 유지합니다.

세부항목 완료일은 기존 `assignmentStates` JSONB의 `completedSubtaskDates`에 ISO 날짜로 저장합니다. 유지한 체크의 날짜는 보존하고, 해제 시 삭제하며 재체크 시 새 날짜를 기록합니다. 날짜 없는 기존 체크에는 임의 날짜를 붙이지 않습니다. 교사 항목 도장판과 학생 세부항목에 `M.D. 요일`을 표시하고 완료 학생 진행도 카드에는 푸른 배경·테두리를 적용합니다.

교사 장기과제 카드는 제목·보상·선택적 마감일과 완료/전체 인원·소형 액션의 2줄 구조입니다. 과제 탭 상단 당일 매트릭스를 제거하여 달력과 장기과제 패널이 바로 표시됩니다. 확인 문구는 `확인 : 선생님` 또는 `확인 : 이름`, 진행도 버튼은 `진행도/도장판`으로 정돈했습니다. 대시보드 미완료 과제는 5개 상태 버튼을 한 줄로 제공하며 즉시 저장·닫기하고 기존 메모를 보존합니다.

검증: 전체 단위 테스트, PostgreSQL JSONB 완료일 저장·보존·해제, 기록·장기과제·대시보드·상점·아바타·반응형 브라우저 회귀 및 체험 HTML 빌드. 테이블·컬럼 추가는 없습니다.

31차의 `schema.sql` 변경은 `startoday_student_payload` 함수에서 본인의 `completedSubtaskDates`를 반환하는 필드 추가뿐입니다. 기존 테이블·컬럼 구조는 그대로이며, 클라우드 학생 화면에도 완료일을 표시하려면 Supabase에 갱신된 함수를 적용해야 합니다.


### 32차: 메모 3종 공개 범위·2자리 연도 표기
대시보드 학생 카드에서는 획득 개수 버튼을 제거하고 칭호 배지만 남깁니다. 교시 편집에는 메모1(`publicMemo`/기존 `memo`), 메모2(`privateMemo`), 메모3(`teacherMemo`) 입력을 제공합니다. 저장·개별 지우기·전체 지우기·실행취소는 세 필드 모두 지원합니다.

- 교사 시간표·달력·편집 모달: 메모1·2·3.
- 교실화면 및 학생 오늘의 일정: 실제 한국 날짜의 오늘에 메모1·2. 메모3은 제외.
- 학생 달력: 과거·오늘·미래의 교시별 메모1. 메모2·3은 응답 데이터에서도 제외.

로컬 `studentCalendarData`와 SQL `startoday_student_payload`의 `calendar.timetables`는 날짜·교시·과목·공개 메모만 투영합니다. 기존 `memo`만 있는 시간표도 호환합니다. `teacherMemo`는 기존 시간표 JSONB에 저장하므로 테이블·컬럼 추가가 없습니다. 클라우드 학생 달력에 메모1을 보내려면 갱신된 `schema.sql` 함수를 Supabase에 적용해야 합니다.

날짜·짧은 날짜·기록 작성/수정 날짜는 `YY.MM.DD.(요일)`로 통일합니다. 한국 시간대와 정확한 요일·월일 0패딩을 유지하며 저장용 ISO 날짜와 타임스탬프는 바꾸지 않습니다. 장기과제 마감일과 항목 완료일에도 같은 형식을 적용합니다.

검증: 전체 단위 테스트, 과거·오늘·미래 메모 공개 범위와 메모3 미유출을 확인하는 SQL 통합 테스트, 실제 교사·교실·학생 화면과 메모 저장/지우기/실행취소·날짜·모바일을 확인하는 `tests/patch32.browser.mjs`, 기존 브라우저 회귀 및 체험 HTML 빌드.

### 33차: 오른쪽 메모 묶음·아바타 옷장·사용 거래
기록 대상일과 작성/수정 시각은 동일한 11px·색상·굵기로 표시합니다. 시간표는 과목을 왼쪽에 크게, 메모1·2·3과 연결 교시 일정을 오른쪽 `.slot-memos`에 세로로 묶습니다. 교사만 메모1의 📢·메모3의 🔒를 보며, 학생·교실화면의 메모1·2는 같은 스타일과 줄바꿈만 사용합니다. 메모3과 기존 공개 범위는 유지합니다. 교시 일정 편집 버튼도 메모 묶음 안에서 동작합니다.

학생 화면 진입·학생 변경·섹션/탭 전환은 맨 위에서 시작합니다. 같은 화면의 데이터 갱신이나 장착/해제는 기존 스크롤을 보존합니다. 별 개수 아래 👕 버튼으로 별도 아바타 화면에 진입하여 내 옷장/옷 가게와 머리·옷·효과·배경 카테고리를 사용합니다. 구매 후 옷장으로 이동하며 보유 아이템은 클릭으로 장착/해제합니다. 프로필과 옷장 미리보기가 같은 장착 레이어를 사용합니다.

기본 샘플은 `assets/avatar/{star-hat,star-cape,star-aura,star-sky}.svg`입니다. 카탈로그를 늘릴 때는 `js/core.js`의 `AVATAR_CATALOG`와 SQL `startoday_avatar_catalog`의 ID·이름·카테고리·가격·상대 이미지 경로를 함께 등록합니다. 카탈로그 일치와 이미지 파일 존재를 테스트합니다. 체험 HTML 빌드에도 SVG를 내장합니다.

소유 목록과 장착 상태는 학생 JSONB의 `avatarOwned`·`avatarEquipped`에 저장됩니다. SQL 학생 RPC `startoday_avatar_buy`·`startoday_avatar_equip`은 본인 인증 후 클래스 잠금 아래 잔액·소유권·중복 구매·서버 가격을 검증하고 학생 응답의 `avatar`를 갱신합니다. 구매는 `아바타구매` 거래로 별코인을 차감합니다. 일반 교사 학생 정보 수정이 소유 아이템을 지우지 않도록 보존합니다.

물품 사용은 원래 거래의 상태를 `사용완료`로 바꾸면서 현재 시각의 `사용` 거래(0별·물품 정보·`originalTxId`)를 추가합니다. 교사 경제 거래표는 일시/학생/종류/내용 4열이며 아이템 거래는 이름만, 지급·차감은 사유와 부호 있는 금액을 보여 줍니다. 학생 거래표는 기존 잔액·상태 표시를 유지합니다.

`schema.sql` 변경 포함: 아바타 카탈로그/인증 RPC/학생 응답, 학생 JSONB 소유 항목 보존, 거래 유형 제약 및 사용 거래 중복 방지 인덱스·사용 처리. 테이블 추가는 없습니다. 클라우드에 적용하려면 갱신된 SQL을 Supabase에 실행해야 합니다. 단위·SQL 테스트는 잔액 부족/중복 구매/미소유 장착/타학생 격리/보존/새 사용 거래를, 브라우저는 날짜 스타일·메모 정렬/아이콘 공개 범위·스크롤·4종 구매/장착·모바일·이미지 로딩을 확인합니다.


### 캐릭터 인사 모션 보강
추가 이미지 없이 기존 캐릭터·의상 레이어에 3.2초 호흡/좌우 ±1.2° 흔들림과 900ms 두 번 콩콩 뛰는 인사를 적용합니다. 발바닥을 축으로 움직이며 그림자도 호흡과 두 번의 도약에 맞춰 수축·팽창합니다. 단발 별가루 대신 오른쪽 위 말풍선에 네 가지 짧은 인사를 랜덤으로 표시합니다.

연타는 이전 타이머를 취소하고 클래스를 제거→리플로우→재적용하여 즉시 다시 시작합니다. 타이머는 캐릭터별 WeakMap으로 관리하며 마지막 입력 후 900ms에 클래스와 문구를 정리합니다. 실제 버튼의 Enter/Space와 키보드 포커스를 유지하고, 선택·탭 하이라이트·이미지 드래그를 차단합니다. 동작 줄이기 설정에서는 캐릭터·그림자·말풍선 애니메이션을 끄고 말풍선을 숨깁니다.

**`schema.sql` 및 이미지 파일 변경 없음.** 단위 테스트는 연타 시 타이머 한 개 유지·리플로우·랜덤 네 문구·정리를, 브라우저는 정확한 호흡/회전/두 번 도약/그림자·즉시 재시작·장착 레이어·키보드·선택 방지·모바일 말풍선/머리 잘림 방지·동작 줄이기·데이터 무변경을 검증합니다.
