# Reference Instructions — `logo-guidelines`

Read this file, `../../shared-references/research-reference-standard.md`, `logo-research-protocol.md`, and `logo-guideline-structure.md` before any logo-direction or usage-guideline work. Ask the user only the unresolved identity facts that affect logo research; inspect the brief and logo folder first.

**Approval gate:** After inspecting supplied files read-only, ask only missing identity facts or whether the request is pre-design direction versus rules for an approved logo. Wait for the user to confirm that mode and the research scope before searching project-specific logo cases, analyzing references, or drafting the guide.

## Pick the correct mode

| State | Work to do | Do not do |
|---|---|---|
| No approved logo exists | Create **pre-design Logo Direction Guidelines**: research-backed strategy, route, form/script constraints, palette behavior, tests and avoidances; then obtain user approval and route to `../../logo-design/SKILL.md` or `../../logo-text/SKILL.md` | Do not invent clear space, grid, minimum size, approved variants, or present a usage manual for an absent mark |
| Approved logo master exists | Write evidence-based **post-design usage guidelines** from the exact authoritative file and owner approvals | Do not redraw the mark or publish guessed measurements, colors, type, variants, or co-branding rules |
| Logo status/ownership unclear | Ask which file/variant is authoritative and whether it is approved | Do not assume the newest or largest image is the master |

## Research specifically for logo decisions

Open at least five distinct relevant project pages and inspect the actual mark images. Prefer real commissioned/official identity projects; use concept/student work only as labeled supplemental references. Balance by category, audience, country, and writing system. For Arabic/bilingual marks, include actual Arabic wordmarks and inspect RTL joins, ligatures, counters, diacritics and hierarchy. For each page, analyze the logo route, silhouette, construction, negative space, reduction behavior, color use, script, variants, guideline diagrams, and application evidence only where visible. Verify whether technical claims are measured or simply illustrated.

Search for project pages via the logo library, Behance, Google Images and web queries. Use Agent Reach for supported public reading; use a visual-capable browser for pixels. If a public source image must be fetched to inspect it, follow the shared standard for temporary permitted use; never include the reference image in the user's final prompt or repo. Record page and image status separately. Use the standard visual-analysis card and state source limits.

## Pre-design direction decision map

- **Literal product symbol** only if it is distinctive and useful at real size; compare against category clichés.
- **Metaphoric mark** only when the metaphor is supported by a true name/story/offer fact; explain the connection and alternative reading.
- **Abstract/geometric mark** only when a concrete design rationale is approved; define memorable structure rather than an unanchored shape.
- **Wordmark or Arabic typography** when the name/script is the strongest recognition asset; route to `logo-text` when the user wants no separate symbol.
- **Monogram/emblem/combination** only when use case and name length support it; define the hierarchy and small-size behavior.
- **Existing-logo refinement** is not a new direction: route to `../../logo-prompting/SKILL.md` with the authoritative file and one change at a time.

The guide should compare at most 2–3 directions. For each, state: brief evidence; recommended logo route; concrete meaning anchor; form/script behavior; exact approved color roles; use and scale test; risk; references and originality boundaries. Recommend one with a reason, but don't decide for the user. Ask for approval before logo concept questions or prompts.

## Post-design usage rules

For an approved logo, record source filename and format, approved variants, spelling, color/background behavior, use cases, and known limits. Only state construction, clear-space, min-size, or contrast thresholds when measured from the vector/source and owner-approved. Test actual intended contexts (small avatar, print, signage, embroidery, etc.) instead of assuming one universal rule. Use a human-editable guide as the source of technical truth; an image model may only style a layout, not invent its data.
