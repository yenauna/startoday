# Logo Research Protocol

Use this protocol before proposing a new logo direction. The [Logo Design Reference Library](../../shared-references/logo-design-reference-library.md) is a starting set of direct Behance projects; it is not a substitute for opening current source pages or checking the actual images.

## Select useful evidence

Choose at least five distinct projects. Prefer a balanced set that answers different questions:

1. A logo with a comparable audience/category or use environment.
2. A project with the same writing system or a credible bilingual counterpart.
3. A wordmark/letterform or symbol structure that tests the selected route.
4. A clear logo variation, color, reversal, or small-size system.
5. A project that documents guidelines, pattern derivation, or real applications.

If a relevant dimension is missing from the library, search the open web for primary creator/project pages and add the new source to the research log. Avoid collecting five near-identical logo galleries. Count distinct projects, not screenshots or variants of one project.

## Open and inspect

1. Follow the `agent-reach` skill for source access. Use native public search/read tools first, and use Agent Reach for supported gaps. For actual visual inspection, use an image-capable browser or image viewer. A text result, title, description, thumbnail label, or image-search caption alone is not a direct visual inspection.
2. Open the canonical project page and inspect the logo images and relevant guideline pages. If the source is blocked, stop according to Agent Reach rules; do not bypass login, CAPTCHA, rate limits, or platform controls.
3. If the page is readable but the images do not load, mark the page as text-read / images-unavailable. Do not promote its description into a visual observation.
4. Do not download an image to the repository. If a permitted public asset must be fetched transiently to inspect it, keep it temporary and local; do not publish the asset or infer reuse rights.

## Record each reference

| Field | Required record |
|---|---|
| Project | Exact project title and credited maker/studio if stated |
| Direct source | Canonical URL, not a search-results URL |
| Context | Category, market, audience, and intended use only when supported |
| Status | Client/commissioned, student, concept, portfolio-only, or unclear |
| Access | Opened, blocked, missing, or timed out; visual inspection yes/no |
| Observation | Specific visible form/system evidence, without evaluation |
| Interpretation | What the visible choice may do for the stated brief |
| Transfer | A generalized design method that could be tested for this brand |
| Boundary | Exact distinctive feature that must not be copied |

## Synthesis

- Compare decisions, not aesthetic labels: mark-versus-wordmark, stroke/weight behavior, counters/negative space, script joins, silhouette, contrast, reduction, variants, and relationship to a pattern.
- Recommend no more than two transferable principles from any one project.
- Remove the original names and signature visual details from any downstream prompt.
- State uncertainty when the source gives no brief, market, client status, or production proof.
- For a complete scan, report the number of distinct pages opened and the number whose relevant images were actually inspected. Keep both numbers; never collapse them into one.
