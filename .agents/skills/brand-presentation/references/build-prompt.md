# Standalone Brand Presentation Build Prompt

Use this as an implementation brief after the inputs are approved. Replace every bracket with a verified fact. If required assets or copy are missing, stop and ask instead of inventing a placeholder.

“Create one standalone, responsive HTML file at [approved output path] for the approved identity of [brand]. Read the project's locked brief at [AGENTS.md / brief.md] and use the approved assets in [asset folders]. Before coding, inventory each real file and map its intended section. Do not redraw or recolor the approved logo. Do not invent product claims, colors, fonts, taglines, mockups, or usage rules.

The page should present this story in one continuous scroll: [approved short introduction], the identity idea, approved logo variants, exact palette with hex codes and roles, approved typography shown in real copy, confirmed usage rules where available, and selected applications in customer-journey order. Omit a section when its information or approved asset does not exist; ask if the omission changes the requested deliverable.

Choose a unique layout system from the brand personality: [brief traits]. Define [grid, page width, section rhythm, image scale, section backgrounds, and type scale] so the page itself expresses the identity. Use the reference library only to study broad sequencing or composition methods; do not copy recognizable work.

Technical requirements: one .html file with inline CSS and vanilla JavaScript only; no framework, build step, or external runtime. Use relative paths for supplied image files, sensible system font fallbacks, CSS custom properties for approved colors, semantic headings, descriptive alt text, keyboard-visible focus for controls, and responsive layouts. Keep the markup readable and add short section comments. Do not use remote assets unless the user has approved them and the page must be online.

Before delivery, open the file and inspect desktop and mobile widths. Confirm each referenced asset loads, colors and copy match the brief, text is readable, no section overflows, and the page opens locally by double-click. Deliver the path and a short summary of what is shown.”

## Content map template

| Section | Approved source | Evidence needed | Present? |
|---|---|---|---|
| Opening / cover | Brief and approved copy | Brand name, positioning line, hero asset | Yes / omit / ask |
| Identity idea | Brief | One sentence about the approved concept | Yes / omit / ask |
| Logo | Approved logo files | Correct variants and backgrounds | Yes / omit / ask |
| Palette | Locked brief | Exact hex, role, and usage | Yes / omit / ask |
| Typography | Locked brief | Exact font names, script, hierarchy | Yes / omit / ask |
| Rules | Approved guidelines only | Clear space, min size, misuse rules | Yes / omit / ask |
| Applications | Approved mockups | Customer-use order, captions, alt text | Yes / omit / ask |

Do not use a gray “placeholder” image or sample text that could be mistaken for approved brand content.
