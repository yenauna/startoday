# Brand Brief Authoring Prompt

Use this prompt to build a decision-ready brief from a brand conversation. Read `identity-questionnaire.md`, `personality-archetypes.md`, and `color-psychology.md` first. If references are requested, use `../../shared-references/visual-analysis-workflow.md`.

“Create a complete, coherent brand system for [brand/project] using only the user's statements, supplied assets, and verified source material. First extract facts and existing decisions from the project files. Ask concise questions only for missing decisions that change the strategy or system, including exact name/script, offer, audience/market, promise/proof, intended price/experience tier, products/variants, approved logo and source assets, palette, type/script, touchpoints, and constraints. Do not invent facts, claims, product variants, language/dialect, colors, visual assets, or geography.

Summarize the audience's needs and the brand's offer. Define one clear positioning opportunity, the intended tier, and list evidence or open questions. Translate the approved positioning into a connected system: logo behavior, palette roles, type hierarchy and script behavior, supporting graphic devices, image direction, voice, layout behavior, and rules for the selected touchpoints. State how these elements reinforce one another and which identity codes remain consistent across applications. If visual research was requested, compare distinct public case studies, record direct links and project status, and describe transferable methods plus elements not to copy. Do not derive the client's colors, logo, or distinctive assets from a reference.

Offer a small number of genuinely distinct visual routes, each tied to the brief: positioning, audience perception, logo/shape behavior, palette roles with candidate exact hex codes, type/script direction, supporting graphics, image behavior, voice, touchpoints, and trade-offs. Explain what makes the route recognizable and how it works beyond a hero logo. Label all values as proposed until the user approves them. Check color contrast for intended text/background use before recommending a combination. If the user asks for “premium,” ask what tier and experience they mean and translate it into deliberate design behavior; do not default to black/gold, serif type, minimalism, metallics, or other prestige clichés.

For product/beauty brands, include only confirmed products, hero SKU, names/variants, approved variant-coding rule, pack formats, supplied product/packaging assets, and exact approved copy. Keep ingredients, efficacy, safety, sustainability, origin, clinical/testing, certification, and regulatory claims open unless the user provides approved source text. Do not invent labels just to make packaging look finished.

Return a coherent brief with status labels: LOCKED, PROPOSED, or OPEN. Include exact approved hex codes only when supplied or confirmed; spell out each palette role and intended surface. Cover strategy, scripts, market, audience, offer, promise/proof, differentiation, logo system, type hierarchy, graphics, imagery, voice, applications, products if relevant, production/accessibility constraints, asset filenames/approval status, and source links. End with the specific decision needed before the next selected stage. Do not generate an image prompt until the brief and required identity inputs are confirmed.”

## Compact brief output

| Field | Value | Status/source |
|---|---|---|
| Name and scripts | [exact spelling] | [status/source] |
| Offer/category | [what it does] | [status/source] |
| Market and audience | [country/region, audience, need] | [status/source] |
| Promise and proof | [supported outcome and evidence] | [status/source] |
| Differentiation | [specific opportunity] | [status/source] |
| Personality | [one or two traits plus plain-language read] | [status/source] |
| Intended tier and positioning | [customer's intended experience/value cue] | [status/source] |
| Palette | [exact HEX + roles] | [status/source] |
| Logo and asset system | [approved files, variants, restrictions] | [status/source] |
| Typography/language | [hierarchy, scripts, reading direction] | [status/source] |
| Graphic and layout system | [motif, grid, spacing, signature behaviors] | [status/source] |
| Imagery/voice system | [visual treatment and writing behavior] | [status/source] |
| Product/variant architecture | [confirmed SKUs and shared/differentiating rules, if relevant] | [status/source] |
| Touchpoints | [real customer contexts] | [status/source] |
| Constraints/open questions | [items] | [status/source] |
| References | [direct URLs and “do not copy” notes] | [source/status] |
