# Reference Instructions — `mockup-prompting`

Read this file, `../../shared-references/research-reference-standard.md`, `mockup-types-by-business.md`, `prompt-patterns.md`, the identity file, and the exact logo, palette/system board, product artwork, and requested placements before writing prompts. Mockup prompts remain in `prompts.md` during a full branding flow.

**Approval gate:** Audit supplied files read-only, ask only missing decisions that change customer use, touchpoint, market, product, or assets, then wait for the user's approval of the selected mockup modules and research scope before project-specific web/image research or prompt/file output.

## Interview for decisions that change the scene

Audit supplied inputs first. Ask only: which product/touchpoint is commercially important; who sees it and where; clean product mockup or narrative scene; actual SKU/packaging/material; logo variant/placement; exact copy; format/crop; country/region and context if real-world; and which assets can be attached. If brand identity, approved logo, palette, or actual packaging is missing, ask for it or explicitly keep the affected concept provisional. Don't ask generic “what style?” when the brief and visual research can resolve useful options.

## Required reference research

For a full mockup pack, inspect **at least five distinct global and five distinct Arabic-market project pages**—ten unique pages total. Select by sector, audience, target country, language/script, touchpoint and material. Open every canonical URL and visually inspect the real identity plus relevant application images. A thumbnail or product photo without identity context does not count. Record market and project status only as source-supported. Follow Agent Reach's read-only/platform rules, use an image-capable tool for the visual layer, and record inaccessible links. Do not copy mockup scenes, product label layout, graphics, colorways, photo props or recognizable compositions.

For each image, note: what physical/digital object is shown; logo version, position and approximate scale; label/content hierarchy; material and finish; brand color coverage; type/script legibility; camera angle/crop/depth of field; lighting and background; whether the scene supports actual customer use; and one no-copy boundary. Distinguish objective visual details from a hypothesis about why they work.

## Route mockups by customer use

Rank candidate touchpoints by customer journey and brand need. Avoid a generic pile of cups, bags, shirts and storefronts. Confirm whether a real product, package, digital UI, retail environment or campaign scene is relevant. For every selected prompt, build an attachment manifest: exact approved logo file; exact palette/design-system board if available; `brand identity.txt`; real SKU/product/package art; exact approved copy. State what each upload controls. The client's logo/system outranks inspiration references.

## Prompt and quality rules

Name the true material, scale, fabrication limits, country/region, camera/crop, lighting, hierarchy and output ratio. Repeat exact HEX values and roles even when a board is attached. Tell the image tool to use the actual logo upload visibly and immutably. If text or logo fidelity is unreliable, request a clean accurately sized placement area and composite the source file later; label this provisional. Check logo fidelity, crop, believable material, label hierarchy, actual-use context, consistency, exact spelling, non-invented claims, and no recognizable reference copying. A pretty mockup is not proof of manufacturability or legal/regulatory approval.
