# Reference Instructions — `brand-compass`

Read this file, `../../shared-references/research-reference-standard.md`, `../../shared-references/subagent-collaboration-protocol.md`, the approved `brand strategy.md`, `brand identity.txt`, and any relevant guideline before advising. This is a standalone decision-support skill; it does not require `lets-brand`.

## Interview only when the decision is under-specified

First inspect the proposal/asset and its governing approved principles. Ask up to 3–6 pivotal questions only if an answer could change the recommendation: who is affected; what action or promise is proposed; what proof exists; where and how it will be used; which constraints are real; and what success means. Treat the user's explicit question and supplied scope as authorization to review that decision. Do not request a second approval of the same scope, and do not ask for routine preferences.

If a strategy file is missing, conflicting, or not approved, label that status. Ask whether to route into `brand-strategy` or give a clearly provisional recommendation from the available facts. Never silently convert an inference into a rule.

## Use a decision trace, not a taste verdict

Score no more than the dimensions that matter to this decision. For each, cite the actual approved principle or evidence and explain the consequence:

| Test | Ask |
|---|---|
| Audience fit | Does the choice serve the priority audience in the stated situation? |
| Position fit | Does it reinforce or blur the brand's chosen category/value? |
| Promise and proof | Does it make a claim the brand can actually deliver and substantiate? |
| Distinctiveness | Does it preserve meaningful difference without copying a competitor? |
| Experience fit | Can the organization deliver it consistently at the relevant touchpoint? |
| Identity fit | Does it respect approved voice/visual rules while allowing context-appropriate expression? |
| Risk and trade-off | What customer confusion, exclusion, credibility, operational, cultural, or reputational risk follows? |
| Evidence confidence | Is the basis an approved rule, reliable evidence, a source observation, or an assumption? |

Do not turn this into a numeric grade unless the user needs comparisons. A decision can depart from a visual convention and still fit the strategy. Label recommendations, interpretations, and unknowns.

## When to research

Prefer the approved strategy and user's own evidence for a simple on-brand check. Search public sources only when a missing factual question, current market condition, category norm, or requested benchmark could change the answer; ask and get approval for that research scope first. For a visual-direction decision, follow the shared five-project/actual-image requirement. Use Agent Reach under its read-only, login, rate-limit, and block rules; use image-capable tools for pixels and never claim inspection from a title or snippet. Record direct sources, observations, interpretations, method transfer, and copy boundaries. Do not research a competitor merely to borrow its look.

## Response contract

Deliver a concise, decision-ready response with:

1. **Recommendation:** fits / fits with changes / conflicts / insufficient evidence.
2. **Why:** the one or two approved strategy rules that decide it, with evidence status.
3. **Do:** specific actions that improve strategic fit.
4. **Avoid:** specific choices that weaken the promise, proof, clarity, or distinctiveness.
5. **Change if needed:** the smallest viable revision and one alternative if useful.
6. **Next route:** the relevant specialist only if the user asks to execute it.

When the user asks for a file, add the requested decision record to `brand decisions.md` only if asked; preserve existing decisions and status. Never silently update the strategy or identity source of truth.
