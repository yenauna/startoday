# Reference Instructions — `brand-guidelines-doc`

Read this file, `../../shared-references/research-reference-standard.md`, the selected guideline template/prompt, existing identity file, actual logo/color/type assets, and owner-approved policies before writing. First ask whether the user wants a writing prompt, visual board prompt, actual written guide, review checklist, or a chosen combination.

**Approval gate:** Audit supplied files read-only, then ask only decision-critical gaps (maximum 3–6 in one round). Wait until the user approves the guide type, audience/sections, and research scope before project-specific source research, drafting, or editing files. Do not ask again about facts already approved in the identity file.

## Separate this skill from logo guidelines

- Use `../../logo-guidelines/SKILL.md` first for research-based pre-design logo direction or technical usage rules for an actual approved logo.
- Use `brand-guidelines-doc` for a fuller written identity/voice/messaging document, governance, content examples, or cross-asset checklist.
- A visual logo-guidelines board is a presentation of approved, verified facts; it is not authority for inventing logo geometry or measurements.

## Research applicable guideline systems

Inspect at least five distinct actual guideline manuals/identity systems relevant to the selected sections, industry, audience and market. Review real guideline pages/screens—not just marketing cover images. For voice guides, inspect actual voice principles and examples; for logo guides, examine actual approved variants, measured clear-space/minimum-size basis, misuse demonstrations, color/typography rules and usage context; for checklist/governance work, inspect actual approval/version/ownership cues. Record what the source presents, the confirmed owner/source, any missing evidence, and one reusable teaching method. Do not copy a competitor's rules or wording.

## Choose sections by need, not by template size

Ask about audience (staff, agency, printer, partner), usage scenario, approved claims, exact selected sections, accountable owner, maintenance/version cadence if relevant, and output format. Don't ask easy styling questions already settled by the identity file. Include only sections that help the named reader make a decision: positioning; voice; message hierarchy; approved copy; palette/type; logo use; imagery/graphics; applications; accessibility/production notes; approval checklist; ownership/version.

## Accuracy branches

- **No approved identity/voice** → return to `brand-identity` or mark proposed language as options awaiting approval.
- **No approved logo** → don't invent clear space, minimum size, construction grid or official variants. Use pre-design direction from `logo-guidelines` and label later rules open.
- **Approved logo exists** → use exact supplied master/variants. Include only owner-approved or reliably measured rules; mark uncertain values provisional.
- **Visual board only** → allow image tools to design layout, but set exact assets/text/colors externally; label generated measurement/typography error risks.
- **Written guide** → write actionable rules and examples, distinguish “must” from recommendation, cite source owners, name prohibited claims, and include a review/version block.

The final guide or prompt should be usable by the stated reader without making up policy. Verify every HEX, font/license, logo file, claim, numeric rule, and contact/approval owner. Never call an internal review a legal, accessibility, print or trademark certification.
