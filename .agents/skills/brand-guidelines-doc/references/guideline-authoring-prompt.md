# Brand Guidelines Authoring Prompt

Use this prompt to create a written guide from an approved brief. Adapt its scope to the user's request; do not complete empty template fields with guesses.

“Write practical brand guidelines for [brand name] using only the locked brief at [project brief path], approved logo and mockup files at [asset paths], and user-approved copy. Read the related references for the requested topics. Preserve every exact brand value: spelling/script, color hex and role, font name, voice trait, and approved claim. Do not invent numeric logo rules, minimum sizes, color ratios, accessibility results, production requirements, regulatory copy, or customer promises. Mark any missing decision as OPEN and identify who can confirm it.

The intended users of this guide are [roles/audience] and their main channels are [channels]. Write in [language and script], using the brand's approved voice. Give clear actions, short examples, and useful do/don't pairs. Each rule should say where it applies and what a reviewer can check. Explain the reason only when it helps the user make a decision.

Include only the sections requested: [voice / messaging / visual identity / logo usage / color / typography / imagery / assets / consistency / approval]. For each section, cite its source in the project files or mark it as a proposed recommendation. Use example designs only as methods; do not reproduce their logo, palette, text, illustration, or layout. Keep draft work distinct from approved work.

Before delivery, check the guide against the locked brief, the actual logo files, exact hex values, script direction, and selected channel requirements. Remove contradictions and unverified fixed values. Save as [output path] and provide a concise list of confirmed rules, open decisions, and source files used.”

## Rule-writing format

For every important rule, use:

- **Rule:** one clear instruction
- **Where it applies:** channel, surface, or context
- **Reason:** practical design or brand purpose
- **Example:** approved asset or short, original example
- **Status/source:** confirmed from file, measured, owner-approved, recommendation, or open

## Approval-status labels

- **Approved:** confirmed by the user or an approved source file.
- **Measured:** measured from an asset, with method and asset version recorded.
- **Recommended:** a design proposal that still needs owner approval.
- **Open:** a missing or conflicting decision; do not present it as policy.
