# Asset Approval Checklist

Comprehensive checklist for reviewing marketing assets before approval.

## Quick Review

Before detailed review, verify:
- [ ] Asset serves stated purpose
- [ ] Target audience appropriate
- [ ] No obvious errors or issues
- [ ] Aligns with campaign goals

## Visual Elements

### Logo Usage
- [ ] Correct logo variant for context
- [ ] Approved clear-space rule maintained, if one exists
- [ ] Minimum size rule met, if one has been approved; otherwise the actual context has been checked
- [ ] Approved colors only
- [ ] No unauthorized modifications
- [ ] Appropriate for background

### Color Compliance
- [ ] Uses brand palette colors only
- [ ] Color balance follows the approved brand direction for this specific asset
- [ ] Semantic colors used correctly
- [ ] No off-brand colors introduced
- [ ] Consistent across all elements

### Typography
- [ ] Brand fonts used throughout
- [ ] Correct font weights applied
- [ ] Proper type hierarchy
- [ ] Appropriate sizes for medium
- [ ] Line heights adequate
- [ ] No orphans/widows in body text

### Imagery
- [ ] Matches brand photography style
- [ ] Appropriate subjects/content
- [ ] Quality meets requirements
- [ ] Properly licensed/credited
- [ ] Concept imagery and final approved assets are clearly distinguished
- [ ] Optimized for intended use

## Accessibility

### Visual Accessibility
- [ ] Text/background contrast checked against the applicable standard for this use
- [ ] Interactive elements have visible focus
- [ ] Color not sole indicator of meaning
- [ ] Alt text for all images

### Content Accessibility
- [ ] Clear and scannable layout
- [ ] Readable font sizes
- [ ] Logical reading order
- [ ] Meaningful headings structure
- [ ] Links describe destination

## Content Quality

### Copy Review
- [ ] Matches brand voice
- [ ] Appropriate tone for context
- [ ] No prohibited terms used
- [ ] Value proposition clear
- [ ] CTA compelling and clear
- [ ] Proofread for errors

### Messaging
- [ ] Aligns with key messages
- [ ] Differentiators highlighted
- [ ] Benefits over features
- [ ] Target audience addressed
- [ ] No conflicting claims
- [ ] Factual claims, prices, legal text, and required disclosures have an approved source

## Technical Requirements

### File Specifications
- [ ] Correct file format
- [ ] Appropriate resolution
- [ ] File size optimized
- [ ] Proper naming convention
- [ ] Source/approval status and relevant metadata recorded when available

### Platform Requirements
| Platform | Verified |
|----------|----------|
| Instagram | [ ] Correct dimensions |
| Twitter/X | [ ] Meets requirements |
| LinkedIn | [ ] Professional standards |
| Facebook | [ ] Guidelines compliant |
| Email | [ ] Size under 1MB |
| Web | [ ] Optimized for web |

## Legal & Compliance

### Intellectual Property
- [ ] Stock images licensed
- [ ] Music/audio cleared
- [ ] No trademark violations
- [ ] User content authorized
- [ ] Credits included where needed

### Regulatory
- [ ] Required disclosures present
- [ ] No misleading claims
- [ ] Pricing accurate
- [ ] Terms linked where needed
- [ ] Privacy compliant

## Common Issues & Fixes

| Issue | Fix |
|-------|-----|
| Logo too small | Increase to the approved minimum size or recheck legibility where no numeric rule exists |
| Wrong font | Replace with brand font |
| Low contrast | Adjust colors for accessibility |
| Off-brand color | Replace with palette color |
| Blurry image | Use higher resolution source |
| Missing alt text | Add descriptive alt text |
| Weak CTA | Strengthen action-oriented copy |

## Manual Check Support

Check each finished asset against, at minimum:
- Color palette compliance (matches the locked hex codes exactly)
- Current minimum dimensions for its intended use, checked from the official platform/vendor source
- File format appropriate for where it will be used
- Naming convention (see `asset-organization.md`)
- The brand's logo usage rules (`logo-usage-rules.md`)
- Whether every fixed value is approved, measured, or labeled as a recommendation/open decision

## Archival

After approval:
1. Note the asset as approved (date + who approved it) in the project's own tracking (a simple note in `AGENTS.md`/`brief.md` is enough for a one-person or fake-client project)
2. Keep previous rejected/superseded versions in a clearly separate folder rather than deleting them
3. Make sure the approved version is the one actually referenced by `../brand-presentation`'s output
