# Brand Guidelines Doc

Prepares a detailed, ready-to-paste prompt for a writing agent to create a practical brand-guidelines document and, when selected, an image-generator prompt for a visual logo-guidelines board. Prompt-only handoff is the default. Draft the actual document only when explicitly requested. Never invent voice, claims, colors, fonts, or logo rules independently of approved sources.

## When to Use

- Brand voice / tone-of-voice definition
- Messaging framework (how the brand talks about itself, its offer, its audience)
- Detailed logo usage rules (clear space, minimum size, misuse examples) beyond what fits on the presentation page
- A consistency or pre-launch approval checklist for reviewing finished assets against the brand
- Color palette and typography written specs in document form (not just shown visually)
- A prompt for a visual logo-usage, palette, or typography guidelines board

## Quick Start

Read `references/reference.md`, `../shared-references/research-reference-standard.md`, and `../shared-references/brand-intake-interview.md`; audit the brief, logo files, existing rules, and approved copy first. Ask which outputs are wanted: a written-guidelines authoring prompt, a visual logo-guidelines board prompt, the actual written guide, or a selected combination. Confirm the audience, selected sections, approved values, and source files before drafting. Use `templates/brand-guidelines-starter.md`, `references/guideline-authoring-prompt.md`, and (for visual boards) `references/visual-guidelines-prompt.md`. For reference-informed direction, consult both shared design reference libraries and `../shared-references/visual-analysis-workflow.md`; record transferable principles, never copy a named design. Write only the requested sections; do not pad unrelated topics.

## Relationship to the other skills in this collection

This skill does not replace `../brand-presentation` — the HTML page is the visual, shareable deliverable. This skill is for cases where written rules, voice, messaging, or consistency checks need more detail. Always build on the same locked brief from `../brand-identity`; never re-derive colors, name, or personality independently here.

## Accuracy rules

- Distinguish confirmed rules from recommendations and open decisions. Do not invent clear-space units, minimum sizes, ratios, color codes, legal language, production specifications, or accessibility results.
- Use actual logo, color, and type files to verify what can be checked. If a numeric rule needs measurement or owner approval, label it provisional.
- Write examples for this brand's audience, language, market, and channels. Do not fill the guide with generic copy or fictional product claims.
- Align file organization with `../brand-presentation/references/page-structure.md`; any asset manifest is optional and should be simple enough to maintain by hand.
- A visual guideline board generated by an image model is a concept layout only. Use actual logo/vector assets and real, measured rules in the final editable guide; never rely on generated pseudo-Arabic, inaccurate measurements, or invented clear-space rules.
- A request for a prompt is not authorization to generate an image or write the complete guide. Return the selected copy-ready prompt(s) unless the user explicitly requests the artifact itself.

## Note on this skill's origin

Adapted from a general-purpose `brand` skill built for live coding projects (it originally included scripts that synced a guidelines doc to CSS design tokens and a project's `src/`). Those scripts were removed here on purpose — this collection's output is static HTML/AI-prompt work, not a codebase with a build pipeline, so there is nothing for a token-sync script to sync into. Everything below is the written-guidance content only.
