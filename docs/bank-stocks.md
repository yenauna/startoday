# 은행·주식 운영 안내

## 배포

1. 운영 Supabase SQL Editor에서 최신 `schema.sql` 전체를 실행합니다. 기존 자산·상점·월급 계산식은 유지하며 금융 테이블·RPC·거래 유형을 추가합니다.
2. 저장소의 GitHub Actions Secrets에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 등록합니다. 서비스 역할 키는 서버 워크플로우 전용이며 `config.js`와 브라우저 코드에 넣지 않습니다.
3. GitHub Actions의 **Sync stock quote cache**를 수동 실행해 시세를 채웁니다. 평일 09:00~14:30 KST에는 10분 간격 일정으로 실행됩니다. GitHub의 예약 실행은 지연될 수 있습니다.
4. 경제 → **은행·주식**에서 이율·거래시간·정산 대기·환산비율·종목을 설정합니다. 시세 통신이 지연되면 **가격 갱신**으로 우리 반 가격만 직접 입력할 수 있습니다.

운영 DB와 Secrets는 저장소 머지만으로 적용되지 않습니다. 프론트엔드는 외부 주가 사이트에 접속하지 않고 Supabase RPC가 읽은 DB 캐시만 표시합니다. 실제 시세 제공자는 Yahoo Finance의 KRW 종목이며 워커는 통화·가격·기준시각을 검증합니다. 제공자 오류 시 기존 캐시와 기준시각을 유지합니다. 거래 가격은 교육용 포인트 환산 가격이며 실제 증권계좌 거래를 실행하지 않습니다.

## 예금 계산

- 가입 원금은 정수 1~100,000,000포인트, 기간은 2~52주(2주 간격)입니다. 중도 해지는 제공하지 않습니다.
- 현재 누적 별 개수로 이율 구간을 선택합니다. 포인트 집계 기간·월급 모드와 별 개수 집계는 서로 독립입니다.
- 기본 2주 이율: 별 0개 이상 2%, 10개 이상 3%, 30개 이상 4%, 50개 이상 5%. 교사가 하한 구간과 이율을 수정할 수 있습니다.
- 단리 이자 = `floor(원금 × 2주 이율 / 100 × 기간(주) / 2)`. 가입 당시 원금·이율·만기·이자를 확정합니다. 이후 설정 변경은 기존 예금에 소급하지 않습니다.
- 가입 즉시 `예금가입`으로 원금을 차감합니다. 서버 조회·정산 시 만기가 지난 예금은 `예금만기`로 원금+이자를 한 번 지급하고 `matured` 상태가 됩니다.

## 시장가·소수점·정산

- 기본 거래시간은 평일 09:00~14:30 KST이며 종료 분까지 포함합니다. 서버가 실제 KST 시각을 검사합니다. 시간 밖에는 조회만 가능합니다.
- 기본 환산비율은 1포인트 = 100원, 기본 정산 대기는 80분이며 0분이면 즉시 정산합니다.
- 매수 수량 = `floor(최대 매수 포인트 × 환산비율 / 현재가 × 10000) / 10000`.
- 실제 매수 대금 = `ceil(체결 수량 × 현재가 / 환산비율)`. 입력한 최대 포인트를 초과하지 않습니다.
- 매도 대금 = `floor(매도 수량 × 현재가 / 환산비율)`. 수량 일부·전량 또는 포인트를 기준으로 계산한 수량을 매도할 수 있습니다. 정산액이 1포인트 미만인 주문은 거부합니다.
- 수량은 `numeric(14,4)`, 주문 포인트는 정수(1~1,000,000,000)입니다. 올림/내림을 대칭으로 적용하지 않아 반복 거래로 반올림 차익을 만들 수 없습니다.
- 매수 주문 시 `주식매수`로 포인트가 즉시 차감되고, 정산 시에만 주식이 입고됩니다. 매도 주문 시 수량이 먼저 차감되고 `주식매도`는 금액 0으로 남으며, 정산 시 `주식정산`으로 포인트가 입금됩니다. 매수 정산도 금액 0의 `주식정산` 내역이 남습니다.
- 체결 가격·수량·환산비율·정산 예정 시각은 주문 당시 확정됩니다. 이후 가격이나 설정 변경은 정산에 영향을 주지 않습니다. 정산은 거래시간 밖에도 실행됩니다.
- 30분 이상 지난 시세나 미래 기준시각은 주문에 사용하지 않습니다. 수동 가격은 해당 학급에만 적용하며 더 새로운 공용 시장 시세가 들어오면 최신 시세를 사용합니다.
- 종목을 비활성화해도 기존 보유 수량은 최신 유효 시세로 매도할 수 있습니다. 워커는 활성 종목과 실제 보유 종목을 함께 동기화합니다.

## 무결성과 확인

은행·보유 주식·주문 테이블은 교사도 직접 수정할 수 없고 금융 RPC만 변경합니다. 학생 RPC는 학급/번호/비밀번호를 인증하며 자신의 예금·보유·주문만 받습니다. 교사 RPC는 학급 소유권을 확인합니다. 기존 경제 거래와 같은 학급 행 잠금, 요청 UUID 재시도 검증, 정산 원장 고유 인덱스로 중복 차감·중복 지급·동시 과매도를 막습니다. 새 데이터는 교사 스냅샷·백업과 학생 경제 payload에 포함됩니다.

화면을 열거나 새로고침하면 서버가 도래한 예금·주식을 정산합니다. 금융 화면이 열린 동안에는 30초마다 예정 시각과 거래 가능 상태를 확인합니다. 로컬 체험판도 같은 정수/수량 계산과 만기·정산 규칙을 적용합니다.

검증: `npm test`, `npm run check`, `npm run build`, `npm run test:sql`, `node tests/finance.browser.mjs`, AGENTS의 기본·확장 반응형 테스트. PostgreSQL 통합 테스트는 실제 운영 DB가 아닌 PGlite에서 실행합니다.
