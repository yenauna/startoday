# 월급 원장과 직업·알바

학생 잔액은 항상 경제 거래 원장의 합계입니다. 칭찬·조언을 남겨도 즉시 포인트가 생기지 않습니다. 기존 설정에 예전 운영 방식 값이 있어도 원장만 사용합니다. 과거 별을 소급해 자동 지급하거나 기존 거래를 다시 만드는 마이그레이션은 없습니다. 교사가 월급 미리보기를 확인해 지급합니다. 별·칭호·분야 통계와 은행 이율의 별 기준은 그대로 유지됩니다.

경제 → 직업·알바에서 교사가 공고를 등록합니다. 정기 직업은 기본 한 달 활동 기간과 정수 포인트 월급, 단발 알바는 활동 기간과 완료 시 알바 분야 칭찬 1개를 안내합니다. 모집 기간과 활동 기간은 별도로 지정합니다. 자동 조건은 누적 별 및 분야별 칭찬−조언 점수이며, 자유 입력 조건은 학생이 읽고 교사가 확인하는 안내입니다.

학생은 모집 기간의 열린 공고에만 지원·취소할 수 있습니다. 자동 조건은 학생 화면과 인증된 서버 처리에서 모두 검사합니다. 다른 학생의 지원 명단·추첨 결과는 학생 응답에 포함되지 않습니다. 교사 대리 접속도 학생 권한으로 처리합니다.

- 선착순: 지원 시각 순으로 미리 체크하며 교사가 최종 확정합니다.
- 추첨: 서버 또는 로컬 처리에서 무작위 결과를 만든 뒤 교사가 별도로 확정합니다. 새 지원·취소가 있으면 추첨 결과를 초기화합니다.
- 교사 직접 선택·직접 진행: 지원자를 확인해 정원 이내로 체크합니다.
- 선발 후에는 지원·취소·공고 수정·삭제를 막아 확정된 계약과 기록을 보존합니다.

정기 직업 선정은 기존 학생별 직업 급여에 합산합니다. 여러 직업을 맡으면 월급을 합치고 기존 수동 직업 급여는 보존합니다. 활동 시작일을 기준으로 월별 급여가 발생하며, 활동 종료일 또는 조기 완료일까지의 활동 월만 인정합니다. 지급 거래의 `jobWageKeys`로 같은 공고·활동 월을 다시 지급하지 않습니다. 미지급 활동 월은 뒤늦은 정산에도 남습니다. 별도의 일할 계산은 하지 않습니다.

정기 직업 완료는 활동명·기간을 담은 일반 기록을, 단발 알바 완료는 알바 분야 칭찬 기록을 학생별로 하나씩 남깁니다. 공고·학생 조합으로 기록 ID를 고정해 중복 완료가 별을 더 만들지 않게 합니다. 알바 칭찬은 월급의 기록 급여에 반영되며 실제 잔액은 지급할 때만 늘어납니다. 월급을 지급한 뒤 같은 날 완료한 알바 칭찬도 다음 정산에서 누락하지 않으며, 칭찬−조언 방식은 남은 조언과 합산해 계산합니다.

`schema.sql` 변경 포함: 공고·지원 테이블, 소유 교사 RLS, 인증 기반 학생 지원/취소 및 교사 관리 함수, 교사 동기화·학생 경제 응답을 추가했습니다. 학급 잠금과 공고 버전으로 동시 지원·선발 충돌을 검사합니다. 운영 DB에는 머지 후 최신 SQL 전체를 별도 적용해야 합니다.
